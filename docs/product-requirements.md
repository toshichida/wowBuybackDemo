## 1. プロジェクト概要

### 1.1 プロジェクト名

トレーディングカード買取システム構築（買取専門店WOW）

### 1.2 ステークホルダー

| 役割 | 担当者（架空名） | 説明 |
|------|-----------------|------|
| プロジェクトオーナー | Alex Smith | 発注者・事業代表。買取事業の運営責任者。 |
| 開発者 | James Chen | システム開発担当。 |
| デザイナー | Sarah Wilson | ロゴ・プロフィール画像・ヘッダー画像等のデザイン作成。 |
| 顧客 | - | トレーディングカードを売却する個人。 |

### 1.3 背景・目的

- 現在、トレーディングカードを業者から仕入れて海外顧客へ転売する事業を運営中
- 業者仕入れでは価格が高く、海外顧客への販売時に約10%の価格差で成約に至らないケースが多発
- 一般顧客から直接買い取ることで仕入れコストを削減し、価格競争力を確保する
- ブックオフ型の買取モデルを採用し、個人からの買取チャネルを新設する

### 1.4 対象商品カテゴリ（初期）

- ポケモンカード 未開封ボックス
- ワンピースカード 未開封ボックス
- AR最低保証カード（高額カード）

※ カテゴリは管理者画面から任意に追加可能とする

## 2. MVPスコープ

本フェーズは**顧客に見せるためのモックアップ**に必要な範囲に限定する。

### 2.1 MVPに含める機能

| 機能 | 説明 | 受入基準（モックアップ） |
|------|------|--------------------------|
| 買取票Webページ | 商品一覧・選択・合計表示 | 商品一覧が表示され、チェックボックスで選択・数量入力・合計金額が自動計算される |
| 買取同意書フォーム | 入力項目・レイアウト | 全14項目の入力フィールドが配置され、送信ボタンでモック送信が可能 |
| 画像生成プレビュー | 3パターンの見た目 | 単品/複数/一覧の3パターンでプレビュー画像が表示される |
| 管理者画面 | カテゴリ・商品のCRUD | カテゴリ・商品の一覧・追加・編集・削除がモックデータで動作する |
| 顧客フローUI/UX | 買取票→同意書の導線 | 買取票から同意書フォームへの導線が確認できる |

### 2.2 スコープアウト（本フェーズでは実装しない）

| 機能 | 備考 |
|------|------|
| X/LINE API連携 | 自動返信・投稿は将来フェーズ |
| スプレッドシート連携 | データ永続化は将来フェーズ |
| 古物台帳の実データ連携 | 将来フェーズ |
| 在庫・仕入れ値管理 | 将来フェーズ |
| 身分証アップロードの実保存 | モックアップではファイル選択のみ |

## 3. ユーザーストーリー（MVP範囲）

### 3.1 顧客ペルソナ

| ID | ストーリー | 受入基準 |
|----|-----------|----------|
| C-1 | 買取票を見て、売りたい商品を選択し、見積金額を確認したい | 商品一覧が表示され、チェックボックス・数量入力で合計が自動計算される |
| C-2 | 買取同意書フォームで個人情報と売りたい商品を入力したい | 全必須項目が入力でき、送信ボタンで送信完了のフィードバックが得られる（実送信はモック） |

### 3.2 管理者ペルソナ

| ID | ストーリー | 受入基準 |
|----|-----------|----------|
| A-1 | カテゴリを追加・編集・削除したい | 管理者画面でカテゴリのCRUDが可能 |
| A-2 | 商品を追加・編集・削除し、買取価格を設定したい | 管理者画面で商品のCRUD・買取価格設定が可能 |
| A-3 | 選択した商品から投稿用画像をプレビューしたい | 3パターン（単品/複数/一覧）でプレビューが表示される |

### 3.3 オーナーペルソナ

| ID | ストーリー | 受入基準 |
|----|-----------|----------|
| O-1 | 顧客フロー全体の見た目・導線を確認したい | 買取票→同意書フォームの導線がデモ可能 |

## 5. 制約事項・前提条件

### 5.1 前提条件

- ロゴ・デザイン素材は Sarah Wilson（デザイナー）が作成
- 初期運用は Alex Smith（オーナー）本人が実施する想定

### 5.2 制約事項

- 品質優先で開発を進め、急いで低品質なものを作らない方針

### 5.3 スコープ外（本プロジェクト全体）

- ECショップの構築（フル機能ショップは不要）
- 海外販売プラットフォームとの直接連携
- 決済システムの自動化（入金は手動で実施）
