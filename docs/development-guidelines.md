## 1. 開発環境セットアップ

### 1.1 必要環境

- Node.js 18.x 以上
- npm または yarn または pnpm

### 1.2 セットアップ手順（例: React + Vite）

```bash
# リポジトリクローン
git clone <repository-url>
cd wowBuybackDemo

# 依存関係インストール
npm install

# 開発サーバー起動
npm run dev
```

技術スタックの詳細は [technical-specification.md](technical-specification.md) を参照。

## 2. コーディング規約

### 2.1 言語別

| 言語 | 規約 |
|------|------|
| TypeScript | 厳格モード有効。型を明示的に定義する。 |
| React | 関数コンポーネント + Hooks を使用。 |
| CSS | Tailwind CSS または CSS Modules を優先。 |

### 2.2 Lint / Format

- ESLint: 推奨設定を適用
- Prettier: 2スペース、シングルクォート、末尾カンマあり
- コミット前に `npm run lint` を実行

---

## 3. ブランチ戦略・コミットメッセージ

### 3.1 ブランチ

| ブランチ | 用途 |
|----------|------|
| main | 本番相当の安定版 |
| develop | 開発統合ブランチ |
| feature/* | 機能開発（例: feature/buyback-ticket） |

### 3.2 コミットメッセージ

```
<type>: <subject>

例:
feat: 買取票に商品選択機能を追加
fix: 合計金額の計算バグを修正
docs: 機能設計書を更新
```

| type | 説明 |
|------|------|
| feat | 新機能 |
| fix | バグ修正 |
| docs | ドキュメント |
| style | フォーマット |
| refactor | リファクタリング |

## 5. モックアップ品質基準

顧客デモで見せられる完成度を目標とする。

| 項目 | 基準 |
|------|------|
| UI | デザインカンプまたはワイヤーフレームに沿った見た目 |
| 導線 | 買取票→買取同意書の流れが操作可能 |
| レスポンシブ | スマートフォン（375px）で表示・操作が可能 |
| エラー表示 | 必須項目未入力時に適切なフィードバック |

---

## 6. 品質優先の方針

- 急いで低品質なものを作らない
- 不明点は発注者（Alex Smith）に確認してから実装する
- ドキュメントと実装の整合性を保つ
